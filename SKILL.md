# Chief of Staff

The chief plans, delegates, supervises, and reviews from the main checkout. Pi Babysit is the execution and coordination substrate: reusable Pi subagents for reasoning and implementation, supervised processes for commands, checks, servers, and PR watchers. Worktrunk owns worktrees; Herdr provides visible terminals and Hunk reviews when needed. Do not require a visible Herdr agent for every background worker.

Defaults: `openai/gpt-6-astra` with medium reasoning for the chief, and `openai/gpt-6.1-sol` with medium reasoning for workers. Verify these exact IDs with `pi --list-models`; honor user overrides. If a default is unavailable, ask for a replacement rather than silently substituting. Verify the chief's current model rather than claiming it changed. For Babysit subagents, select the worker explicitly with `model: "openai/gpt-6.1-sol:medium"`.

Read [the Babysit coordination protocol](references/babysit-coordination.md) before delegating. Read [PR supervision](references/pr-supervision.md) when a task can open or update a PR. For high-risk changes, also read [the Hunk handoff](references/hunk-handoff.md).

## Operating rules

- **Supervise all shell work.** Use `babysit_run` for commands, including Git, Worktrunk, Herdr, builds, and GitHub CLI. Use file tools for reading/editing. No bare shell tool, `nohup`, shell backgrounding, or unsupervised agent launches.
- **Default to asynchronous execution.** Start independent workers and long processes without `foreground`. Give every meaningful run a stable, task-specific name; record the returned ID, not a guessed name. Use `foreground: true` only for one result needed now. Never issue sibling foreground runs in parallel.
- **Wait on events, not repeated status checks.** Background processes notify on exit: normally end the turn and let the notification resume the chief. Use `continueAfterStart: true` only for concrete non-polling work, such as starting the other independent checks and collecting them in one multi-wait. Background subagents must be collected with `babysit_wait` before the parent task finishes; use `mode: "any"` to handle whichever worker finishes first. A ready-to-collect reminder is not the collected result.
- **Chief-mediated communication.** `babysit_send` steers a running child or starts a follow-up task on a confirmed settled child. Workers report through their normal output/final result; the chief collects and routes decisions/dependencies. Babysit is not a peer messaging broker: do not invent peer rosters, ask/reply threads, or worker-to-chief send calls.
- **Bound and preserve work.** Choose realistic budgets/timeouts and an idle reuse window. Defaults are a 15-minute subagent timeout and 120-second idle reap; long implementation, CI, or human-review workflows need explicit settings. Worktrees are not sandboxes. Never treat delivery, agent settlement, passing CI, or an open PR as proof of approval or integration.

## Workflow

1. **Prepare and reconcile.** Verify the loaded `babysit_*` tools, installed pi-babysit README/tool schema, `babysit --version` (at least 0.13.0 for the documented extension), `pi --help`, models, and `wt`. Inspect `wt hook show`, `wt list`, and `babysit_check { state: "all" }`. For PR work, verify `gh` authentication without exposing credentials, `gh extension list`, and `gh observer --help`; use the selected `fini-net/gh-observer` extension rather than a custom watcher script. Load Herdr's skill (`herdr --skill` if absent) and require `HERDR_ENV=1` only before using Herdr layout/review controls. After resume/reload, reconcile the task ledger, current Babysit namespace, worktrees, and PR head SHAs before relaunching. Reuse live workers where possible; do not duplicate a possibly delivered assignment.
2. **Assess risk first.** Record each assignment's risk and reason before creating tasks or launching workers. Low risk means limited impact and easy reversal. High risk includes access controls, payments, sensitive data, destructive changes, migrations, production releases, broad impact, or uncertain consequences. Reassess when findings change scope or risk; pause affected work for a decision.
3. **Isolate and establish ownership.** Create an editing task's worktree with `command wt -C <repo> switch --create <branch> --no-cd --format=json`. Read the returned path and capture the starting commit as `<base>` before edits. Verify setup hooks, including any background setup, or use the repository's documented setup. Allocate one editing worker per worktree; parallelize only independent assignments. Track task, risk, model, branch, base, absolute path, Babysit parent namespace/session IDs, owned process IDs, optional Herdr workspace/panes, PR URL/head SHA, verification, approvals, and next action in a durable ledger outside the reviewed changes. Never store secrets there.
4. **Choose and launch the right worker.** Default to `babysit_run { profile: "subagent", task, model, name, ... }` for reusable Pi workers. **The current tool has no `cwd` parameter; children start in the chief's cwd.** Give the exact worktree path and require absolute file-tool paths, `git -C <path>`, and `cd <path> && ...` in every shell command. Have the worker read that worktree's instructions explicitly. A shell `cd` does not relocate subsequent file tools or Pi's project discovery. If worktree-local configuration/extensions or genuine startup cwd isolation are required, launch `cd <path> && pi ...` as a Babysit **process**, using the process-mode protocol. Honor an explicit non-Pi worker request through the same process supervision, without claiming it has Pi's RPC coordination tools. Omit `agent` unless a matching named definition is known to exist. Set a budget and `timeout` appropriate to the assignment; retain a worker for PR fixes/review with an adequate `reapAfter` window or `reapAfter: "none"`, then explicitly stop it later.
5. **Delegate a complete contract.** Include task ID/revision, goal, ordered steps, scope/files, worktree/base, key decisions, repository rules, risk/reason, acceptance criteria, exact checks, authorized Git/GitHub actions, and deliverable. Require an initial acknowledgement in output and a final status of `BLOCKED`, `PR_OPEN`, `READY_FOR_REVIEW`, or `COMPLETE`, with branch/commit, PR/artifact, checks, and gaps. A blocked worker must stop editing and finish its current task with the decision needed; it must not wait forever for a nonexistent ask/reply channel. The chief answers with a follow-up task. For high risk, establish an explicit Herdr review-host pane and copy the full Hunk handoff with concrete values into the prompt. Workers stay in their assigned worktree and leave integration/cleanup to the chief.
6. **Coordinate while work runs.** Use `babysit_check` for purposeful inspection, blockers, or a narrow log search, not a waiting loop. Use `babysit_send { mode: "steer" }` for revised constraints during work; after collecting a settled result, use `mode: "task"` for a decision, fix, or new phase. Collect the old task before replacing its result window. Route dependencies through the chief and verify the referenced commit/artifact before starting dependent work. Never wait for all long-running tasks before answering an already surfaced blocker. If a worker parks on its own background process, allow its exit notification to resume it; parked is not completed. Inspect startup, state, and logs on failure/timeout before deciding whether to resume, stop, or replace it. Verify actual work and the whole diff against `<base>` regardless of reports.
7. **Deliver and immediately supervise PRs.** Low-risk workers finish local verification and open an authorized PR or save a durable artifact; Hunk is not required. Once a PR is opened, finish that worker phase with `PR_OPEN` so the chief can collect it, record the URL/head SHA, and immediately start a named background `gh observer <full-PR-URL>` through Babysit with `pty: true`. Run independent diff/review work concurrently. Recheck review decisions/comments, changed heads, conflicts, and merge/close state at phase boundaries using the PR protocol; CI completion is not the end of coordination. `gh-observer` is not a general review-comment/webhook feed: declare the owner/next trigger while awaiting human feedback, and require an authorized event source for autonomous late-feedback/new-PR notification rather than pretending a repo TUI provides it. Route failures or actionable feedback back to the same settled worker, reverify, and re-arm watchers for each new head. High-risk workers prepare the annotated Hunk review and return `READY_FOR_REVIEW`; preserve the review/worktree and keep or deliberately resume the worker for feedback. Present decisions to the user and require approval of the current reviewed diff before high-risk integration. Any subsequent diff change invalidates that approval.
8. **Integrate and clean up safely.** Integrate only within the user's authorization. Collect every background subagent's current outcome, including interrupted/failed work. After confirmed integration or approved abandonment, have a live worker finish a stop/handback phase reporting no further editing, final commit, dirty/unmerged state, and owned processes. Stop task-owned workers, watchers, and services with `babysit_kill`; verify terminal state and repository state, including nested task processes. A kill request or waiter timeout is not proof that all work stopped. Preserve deliverables and evidence outside temporary logs, then use `wt remove <branch>`. Close only Herdr resources created for this task, never the main workspace or repository group (`workspace close --group` is forbidden). A reused workspace is not yours to close. Preserve dirty/unmerged work; no force removal. An open PR is not integrated.

If monitoring continues, report the exact active sessions, PR/head, next event/decision, and bounds. Keep the owning Pi session alive: a real Pi quit kills its supervised work. If blocked or no safe path remains, stop with findings, attempted paths, preserved work, blocker, and the next input needed.
